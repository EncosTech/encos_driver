# 七电机集合设备与逻辑 CAN ID

一个集合设备使用一个物理 CAN ID，每个子包由 1 字节 DLC 和固定 8 字节数据区组成。
一个逻辑报文包含 6 槽（54 字节）或 7 槽（63 字节）。
Bus 在发送到适配器前封装子命令，接收侧先投递完整物理帧，再拆分给已注册子设备。
普通设备（子 ID 为 0）保持原有收发行为。

## 地址与创建

内部逻辑地址为 `uint32_t`：bit31–29 存放子 ID（0–7），bit28–0 存放物理 CAN ID。
高三位不属于线上 CAN ID，也不是 SocketCAN 的帧格式标志。帧标志仍使用独立的 `frame_flags`。

```cpp
#include <encos/encos_driver.h>
#include <encos/device/motor/can_address.h>

// 两种方式取得同一个已登记的 Motor。
auto* third = bus->GetMotor(0x123U, 3U, encos::MotorModel::EC_A4310_P2);
auto id = encos::MakeCanAddress(0x123U, 3U);
auto* same = bus->GetMotor(id, encos::MotorModel::EC_A4310_P2);

// 自动读取电机参数时使用命名入口，避免与旧 GetMotor(id, bool canfd) 混淆。
auto* seventh = bus->GetSubMotor(0x123U, 7U);
```

显式子设备创建入口要求子 ID 为 1–7；`MakeCanAddress` 也允许 0，表示普通设备。
物理 ID 必须不超过 `0x1FFFFFFF`。子设备自动使用 FD 容器；物理 ID 大于 `0x7FF` 时自动启用扩展帧。
子设备不能通过 `DisableCanFd()` 关闭 FD 容器；扩展范围的物理 ID 不能关闭 EFF。
这些传输属性不改变所选电机型号或内部 8 字节命令协议。

旧 `int` 接口、Motor 注册表快照和部分绑定输出继续保留有符号索引形式：子 ID 4–7 会显示负数，
其 32 位地址没有丢失。新代码优先使用 `CanId`/`uint32_t`；需要旧接口时用 `LegacyCanIdBits(id)`，
读取旧索引时用 `static_cast<uint32_t>(index)` 恢复完整地址。不要使用有符号整数左移构造子 ID。

Motor 内部不再将地址截断为 16 位。Port 的通配 ID 改用独立标记：默认构造或
`BasePort::kAnyCanId` 表示通配，显式数值 `0xFFFFFFFFU` 是合法的精确逻辑地址。
使用 `IsAnyCanId()` 区分通配状态，不应只比较兼容接口 `GetCanId()` 的返回数值。

## 发送与同步

每槽格式为 `[DLC:uint8][data:8 bytes]`。DLC 的范围为 0–8，表示实际数据字节数，
不是外层 CAN FD 的 DLC 编码；DLC=0 表示空槽，不执行或投递子命令。
子 ID N 的 DLC 偏移为 `(N - 1) * 9`，数据从下一字节开始，槽位不压缩或重编号。
不足 8 字节的数据补零；超过 8 字节或 RTR 命令会被拒绝。
每次新建的集合包全部清零，不保留上次提交的槽数据。
发送包默认含 6 槽；当该包包含子 ID 7 的命令时扩展为 7 槽。
此格式替代旧的无 DLC、7×8 字节格式，收发两端必须同步升级。

非同步发送每条子命令各生成一个包。同步模式中，运动控制先进入现有设备队列，Commit 时按
总线、物理 ID、帧格式聚合。每个子电机的第 N 条待发命令进入该组第 N 个包，不覆盖前一条命令：

```text
子电机 1：A1、A2      子电机 2：B1      子电机 7：G1、G2
包 1：[8:A1][8:B1][0:空][0:空][0:空][0:空][8:G1]
包 2：[8:A2][0:空][0:空][0:空][0:空][0:空][8:G2]
```

`Bus::Commit()`、`Adapter::Commit()`、总线关闭同步模式、适配器关闭同步模式都采用此封装。
不同实际 CAN ID、总线或帧格式不会混包，普通记录形成聚合边界。
保证同一子电机的队列顺序，不提供不同电机之间的全局调用顺序或多包原子执行保证。
现有每个发送通道队列容量和覆盖策略不变。

参数查询、初始化探测等原本立即发送的操作仍立即封装发送，不等待 Commit。
适配器的原始报文接口仍表示物理报文，不自动解释高三位为子 ID。

## 接收

对合法 CAN FD、长度为 54、63 或 64、ID 不含子 ID 的物理报文：

1. 向精确物理 CAN ID 注册的设备投递完整报文。
2. 校验所有完整槽的 DLC；任一 DLC 大于 8 时，不拆分该包的任何子消息。
3. 按槽位顺序查找已注册子路由。DLC=0 跳过；其余只复制 DLC 个有效字节，子消息 len=DLC。
4. 54 字节包最多投递到子 ID 6；63/64 字节包最多到子 ID 7。64 字节包的最后 1 字节作为填充忽略。

6 槽包在物理 CAN FD 上也会补齐为 64 字节，发送端必须将追加的 10 字节置零，
这样第七槽 DLC=0，不会被误识别为子电机反馈。

父设备未注册时仍可投递子设备；父设备已消费报文也继续投递子设备。
不自动创建设备；DLC 非零时，即使有效数据全零也正常投递。任何准确路由或子路由命中后，不再重复进入未知消息邮箱。
原始报文回调只收到一次完整报文，不额外收到拆出的子消息。
普通长度的 `0x7FF` 系统广播保留原行为；54/63/64 字节 FD 集合反馈使用上述精确与子路由规则。

## 传输和协议边界

物理 CAN FD 没有 54 或 63 字节 DLC。SocketCAN/GsUsb 等最终 CAN FD 传输将逻辑包补零至
64 字节；设备固件必须接受该物理长度。EMR2 可保留实际长度，但网关转 CAN FD 后仍为 64 字节。

集合包需要支持 64 字节的 CAN FD 链路，包括 SocketCAN、GsUsb、使用 EMR2 的 Ethernet/RelayWs，
以及固件支持固定小槽分片的 EtherCAT CAN FD 网关。见 [EtherCAT 通信协议](ethercat_protocol.md)。

现有 `SetId`、`SetPos`、`ResetZeroPos` 使用包含 16 位设备地址的广播协议；子设备或超过
16 位的物理地址调用这些操作会返回 false，而不是截断地址发送。存在已注册子电机时，Bus 的
全体重置 ID 和自动分配 ID 同样返回 false。常规扫描仍面向旧设备，不自动发现七个子 ID。

此次修改包含 C++ ABI 变化（Motor 接口、Port 布局），应用和插件应使用同一版本重新编译。
自动化测试不能替代真实集合设备固件的零槽语义、CAN FD 填充和控制时序联调。
