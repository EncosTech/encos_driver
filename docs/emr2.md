# EMR2 中继协议

EMR2 用于 Ethernet 和 RelayWs，扩展 EMR1 的固定 8 字节 CAN 记录。
本实现包含主机编解码、传输接入和能力协商；网关固件、WebSocket 服务端需要独立实现本协议。
EtherCAT/IGH 使用独立的 [PDO CAN FD 分片协议](ethercat_protocol.md#六can-fd-长帧分片)。

## 配置与旧设备兼容

适配器 `extend` 示例：

```json
{"protocol":"auto","max_payload":1448}
```

| protocol | 发送行为 |
|---|---|
| `auto`（默认） | 未取得匹配的能力响应前使用 EMR1；确认后使用 EMR2 |
| `emr1` | 始终发送 EMR1，不进行能力探测 |
| `emr2` | 调用方明确确认对端支持 EMR2，直接使用 EMR2 |

接收端识别两种版本。EMR1 编码保留原有字节布局，不允许超长数据或扩展元数据静默降级。
批量发送先校验整批，再入队；其中一条不可表示时整批拒绝。不能把 64 字节 CAN FD 记录拆成
多个经典 CAN 帧发给旧设备，那会改变设备协议语义。

自动协商使用独立只读能力消息，不用控制指令探测。若旧服务端不能忽略未知能力消息，
使用 `emr1` 禁用探测。已发送命令不会在超时后换版本重发；本协议不提供 exactly-once 执行保证。

Ethernet 的 `max_payload` 范围为 128–1472，默认 1448，表示 UDP 应用载荷（不包含 UDP/IP 头）。
1472 适用于 IPv4 MTU 1500；较小路径 MTU 应相应减小配置，当前不会自动探测路径 MTU。
配置可按总线覆盖，但同一网关的所有通道必须一致，不同网关可分别选择协议。
RelayWs 接受顶层配置，范围 128–65535，不支持 `buses` 覆盖；此预算表示单条 WebSocket
二进制消息中的协议载荷，不保证底层 TCP/IP 不分段。
自动协商取本地预算与对端声明预算的较小值。Ethernet EMR1 额外限制 1448 字节、80 条记录。

## 拆包与执行语义

批次按原顺序拆成独立协议包，只在完整记录之间切分。每包带完整头，独立解析、独立交付，
没有单条记录分片，也没有接收重组。单条记录加头及 TLV 超过预算时直接报错。
一批拆成多个 UDP 包后不保证同时到达、完整到达或同步执行；接收端若要求原子执行，需另行定义协议。

`sequence` 每包递增，`batch_id` 标识一次发送批次，均为 uint32 并允许回绕。
同一批拆出的包共享 batch_id；没有分片总数或“最后一片”字段，不能据此等待重组。
公共编码函数只递增 sequence，批次编号由调用方维护；适配器负责递增 batch_id。
`session_id` 用于关联会话，当前不保证跨进程重启全局唯一，不能作为防重放或鉴权凭据。

## 数据包格式

所有多字节整数为小端，无结构体对齐填充。长度均为实际字节数。

| 偏移 | 类型/长度 | 字段 |
|---|---|---|
| 0 | 4 bytes | ASCII `EMR2` |
| 4 | uint8 | type：1 主机至中继，2 中继至主机 |
| 5 | uint8 | flags，当前必须为 0 |
| 6 | uint16 | header_len，包含固定头与包级 TLV，至少 32 |
| 8 | uint16 | packet_len，完整包长度，最大 65535 |
| 10 | uint16 | record_count，允许 0（心跳） |
| 12 | uint32 | session_id |
| 16 | uint32 | sequence |
| 20 | uint32 | batch_id |
| 24 | 8 bytes | 保留，必须为 0 |
| 32 | 可变 | 包级 TLV，结束于 header_len |
| header_len | 可变 | record_count 条记录 |

每条记录：

| 相对偏移 | 类型/长度 | 字段 |
|---|---|---|
| 0 | int32 | bus_idx；Ethernet 限制为 CAN0–7 |
| 4 | uint32 | CAN ID，标准帧最大 0x7ff，扩展帧最大 0x1fffffff |
| 8 | uint8 | frame_flags，沿用内部消息定义 |
| 9 | uint8 | 数据字节数 len，0–64 |
| 10 | uint16 | 记录级 TLV 字节总数 |
| 12 | len bytes | 数据，不补齐至 8 或 64 字节 |
| 12 + len | 可变 | 记录级 TLV |

frame_flags：bit0 扩展 ID，bit1/bit2 为项目现有 CAN FD 标志组合（必须同时置位或同时清零），
bit3 RTR，bit4–7 禁止。经典 CAN 最大 8 字节；FD 最大 64 字节且不得设置 RTR。
len 是字节数而非 DLC；物理 CAN FD 的 DLC 映射和填充由最终 CAN 传输端处理。

解码器严格检查所有长度、记录数、保留字段、CAN 标志与 ID，拒绝截断或尾随垃圾。
Ethernet 每个 UDP 数据报只允许一个 EMR2 包；EMR1 保留连续多个包的旧接收行为，
总长度不超过 1448、总记录数不超过 80。公共解码 API 也支持连续协议包，任一包非法则整体失败。

## 时间戳与扩展预留

TLV 由 `type:uint16`、`value_len:uint16`、`value:value_len bytes` 组成。
类型 0 无效。类型最高位 0x8000 表示必须理解；当前实现拒绝所有此类扩展。
其他未知可选 TLV 在公共编解码 API 中保留，重复类型按原顺序保留。
包级 TLV 会复制到拆出的每个包；记录级 TLV 随记录移动。

保留以下可选类型：

| 类型 | value 长度 | 用途 |
|---|---|---|
| 1 | 24 | 时间戳元数据 |
| 2 | 12 | 后续时间戳报告与原包/记录的关联信息 |

当前仅固定上述类型长度，value 内容保持不透明；时间戳种类、时钟域、时基、有效性、
硬件/软件来源以及关联字段的最终位布局需在 TSN 接入时明确版本化定义。
不将本机时间擅自解释为同步时间，也不承诺时间戳精度。
硬件发送时间戳需在发送完成后取得，后续应使用独立报告携带关联信息，不能在首次发包前填入真实发送时间。
当前仅支持数据 type 1/2，尚未实现时间戳报告类型、硬件时间戳获取、时钟同步、定时发送或 TSN 调度。

公共 `RelayRecord`/`RelayEnvelope` API 可读写 TLV；普通适配器 `MotorMessage` 回调仅交付 CAN 数据，
不会将时间戳暴露给设备 API。需要强制时间语义的命令目前不应使用可选 TLV，应等待对应能力和 API 实现。

## 能力协商

### Ethernet：EMM1 管理通道

沿用现有固定 64 字节管理包与设备身份。新增 opcode 14（请求）、15（响应），
其他 opcode 与 CAN 配置流程不变。头部格式见
[Ethernet 协议说明](../plugins/adapter/ethernet/README.md#emr2-主机协议支持)。

请求携带 request_id（偏移 8，uint32）及设备 identity（偏移 12，16 字节）。
响应必须回显两者；偏移 28 为协议位图 uint32（bit0 EMR1，bit1 EMR2），
32 为最大应用载荷 uint32（128–1472），36 为功能位图 uint32，40–63 必须为零。
仅接受匹配当前请求和设备身份的有效响应；初始探测最多等待 200ms，无有效响应保持 EMR1。
当前功能位不启用任何 TSN 行为。管理连接失效会使自动协商结果失效，重建适配器重新确认。

### RelayWs：EMC2 二进制消息

在 WebSocket 连接内发送独立的 24 字节消息，不与数据包混合：

| 偏移 | 类型/长度 | 字段 |
|---|---|---|
| 0 | 4 bytes | ASCII `EMC2` |
| 4 | uint8 | 版本 1 |
| 5 | uint8 | 1 请求，2 响应 |
| 6 | uint16 | 固定长度 24 |
| 8 | uint32 | request_id，响应必须回显 |
| 12 | uint32 | 协议位图：1 仅 EMR1，3 支持两者 |
| 16 | uint16 | 最大应用载荷，至少 44 |
| 18 | uint16 | 保留，必须为零 |
| 20 | uint32 | 功能位图，当前不启用 TSN 行为 |

auto 每次连接发送一次能力请求，无响应时保持 EMR1，不阻塞数据流。
有效响应在当前排队批次发送完后生效，避免同一批次跨版本切换。
断线清除旧会话队列与能力，重连重新协商；不会自动重放可能已执行的命令。

## 开销与验证边界

无 TLV 时，EMR1 包大小为 `8 + 18 × N`，EMR2 为 `32 + Σ(12 + len)`。
因此全 8 字节记录比 EMR1 每条多 2 字节，加上包头多 24 字节；短数据能减少固定填充开销。
预算 1448 时，每包最多 70 条 8 字节记录或 18 条 64 字节记录。
元数据和更小预算会减少每包记录数，增加包数、系统调用和分配开销。
当前实现使用 vector 编解码，未承诺零拷贝或给出真实硬件吞吐/延迟指标。

自动化测试覆盖编解码、畸形输入、包边界、旧格式兼容、能力协商及 WebSocket 模拟服务端。
真实网关固件、Windows 网卡和硬件 TSN 性能仍需相应设备联调。

能力查询使用 14/15，避开网关既有的 IP 配置 10/11 与命令 12/13。旧版主机使用 10/11 的 EMR2 自动探测需要同步升级；EMR1 数据与既有管理命令保持兼容。
